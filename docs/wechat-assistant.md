# 微信服务器助手

可以直接问“你有什么功能”“怎么开始训练”“如何连接容器”。常见帮助不依赖模型；其他自然语言交给管理员配置的模型理解。模型可以解释、追问或选择已授权工具，不能自行执行宿主机命令，也不能代替用户确认停止或重启。

## 常用功能

| 消息例子 | 行为 |
| --- | --- |
| 我的容器 | 列出本人的容器、状态、资源、SSH 命令和控制台入口；在控制台查看 SSH 密码、打开 Jupyter |
| 启动 train | 按现有权限和单容器资源上限启动 |
| 重启 train | 返回确认短语，确认后重启；会中断容器内任务 |
| 查看 train 的日志 | 返回最近标准输出，截断长内容并遮盖可识别的凭据 |
| 开启 train 的任务通知 | 在该容器工作区安装任务记录器并订阅通知 |
| 查看 train 的训练任务 | 查看近期记录的状态、退出码与日志末尾 |
| 关闭 train 的任务通知 | 停止通知，不停止任务 |

缺少容器名称会追问，直接回复名称即可。同名容器需要完整 ID。只有唯一已选定的目标时，“启动它”“查看它的日志”才会复用目标。`取消` 清除当前聊天的待确认操作和追问。

每条消息最多执行一个工具。停止、重启确认使用当前消息原文，不能由模型根据历史聊天补出确认短语。模型只能看到有限的用户意图上下文，容器日志、SSH 密码及资源结果不会作为模型上下文上传。含明显密码/密钥内容的历史消息不保留在意图上下文中。

## 训练完成通知

在微信启用指定容器的任务通知后，在该容器终端将原来的任务命令加上前缀：

```sh
python /workspace/.gsm/gsm-run.py python train.py --epochs 20
```

记录器用当前容器用户运行原命令，实时显示输出，保存实际退出码与有上限的日志。使用虚拟环境时可把第二个 `python` 换成虚拟环境解释器路径。原有 `tmux`/后台启动方式仍可使用。

- 退出码 0 标为完成，非零标为失败。进程/容器意外消失只能标为中断，不推断准确退出码或硬件原因。
- 仅跟踪带前缀的新任务；已有进程和 Notebook 单元格不会自动接管。GPU 利用率下降不等于训练完成。
- 每个容器最多同时记录 16 个任务，每份日志约 1 MiB 上限，保留近期约 200 份记录；这些文件计入用户工作区空间。
- 后台定期检查并通过现有微信通道发送，一项任务只产生一条逻辑通知。发送结果未知时不自动重复发送。
- 容器转移、成员失效、微信重新绑定或取消订阅会撤销旧订阅；发送前再次核对权限。
- 微信回复上下文长时间未刷新时，主动通知可能无法送达。可发送一条消息恢复通道，并查询任务记录；不要把微信作为唯一告警通道。

## 部署

更新 API、Server Agent、WeChat Agent 和 iLink 使用的同一 WeChat 镜像。新增记录使用现有 typed records 存储，不需要数据库结构迁移。记录器只在用户明确启用任务通知时安装到对应容器，不批量修改现有容器。

## 验证范围

自动测试覆盖规则/模型选择、目标消歧、权限与配额、确认、防重放、敏感日志遮盖和任务状态。实际部署仍需用可丢弃容器检查记录器退出码、通知送达、取消订阅、接收器重启与权限撤销。不要用用户正在训练的容器测试停止或重启。

当前两级额度审批在网页完成；聊天能读取授权的申请记录，但不能用旧审批命令跳过当前流程。成员私有数据挂载的容器禁止直接转交；任务和项目交接应创建新容器并显式迁移授权文件。
