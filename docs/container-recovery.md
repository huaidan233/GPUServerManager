# 容器停止记录与恢复

容器详情的恢复面板显示最近一次停止、退出码、Docker OOM 标志和最多 40 条事件。
API 定时核对受管容器与 Docker 实例的对应关系后写入持久记录；打开详情也会更新。
记录从部署此功能之后开始积累，不推测缺失的历史。

判断依据：

- Docker `OOMKilled=true`：明确记录了内存不足终止。
- 已完成的停止确认、操作前运行状态、实际执行区间与退出时间吻合：管理系统停止。
- 只有相近的旧审计时间：显示时间相关，不能确认因果。
- 同一次运行中观测到宿主启动标识变化，且停止时间接近启动时间：与宿主重启相关；不推断硬件故障。
- 退出码 0：容器主进程正常退出；不代表内部科研任务完成。
- 其他退出码或缺失证据：原因未确定。137 本身不等于 OOM。

可查看日志、下载包含最近 500 行日志和停止记录的诊断文件、调整停止容器的资源、
检查并启动。启动前验证权限、容器状态、CPU/内存容量和 GPU 编号；提交状态时校验
归属和配置是否仍一致，并使用版本比较更新。恢复容器不会替用户执行训练命令或恢复 checkpoint。

宿主 `/proc` 通过 `/proc:/host/proc:ro` 读取。无需挂载整个根文件系统。
测试通过纯软件模拟宿主重启证据，不主动重启科研服务器。
