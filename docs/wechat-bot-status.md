# 微信机器人：0.3.0 实现状态与边界

本版包含受限自然语言助手和腾讯 iLink 个人微信文字私聊连接器，也保留外部 Webhook 桥接合同。每次部署都需独立完成扫码、配对、网络与实际送达验收；源码测试不能证明任意微信账号已经接通。

## 已实现

| 能力 | 当前范围 |
| --- | --- |
| 配对 | 网页生成十分钟单次码，发送 `/pair <code>`；绑定实时成员身份 |
| 帮助与问答 | 常见帮助可走规则，其他问答依赖管理员配置的主备模型 |
| 容器 | 列本人容器、启动、请求停止/重启并精确确认、读取有界且脱敏的日志 |
| GPU | 查询、需求建议、空闲订阅；不预留、不抢占、不自动停止 |
| 训练通知 | 显式启用记录器，只跟踪带前缀启动的新任务；见[助手用法](wechat-assistant.md) |
| 健康 | 服务器状态及指定容器诊断 |
| 额度 | 可读取有权查看的申请；两级审批在网页完成，不使用旧逐容器审批工具绕过新规则 |
| 打印 | 通用桥接合同可处理附件、草稿与确认；iLink 当前仅文字，不接媒体 |

模型只能选择工具及允许参数；每条消息最多执行一个工具，Central API 再次检查角色、当前成员状态、所有权、个人额度与确认。不能用聊天执行任意宿主机 shell、签发 Agent 密钥或读取其他成员私有数据。网页能力不自动等于聊天工具能力。

## 渠道区别

- **iLink**：提供扫码、长轮询、身份筛选、持久化消息去重和发送幂等。当前限扫码者本人文字私聊，不接受群消息或其他发送者。部署见[个人微信接入](wechat-ilink.md)。
- **Webhook**：`/wechat-agent/inbound` 是项目自定义 JSON/HMAC 接口，不是微信平台原始回调。桥接服务必须先完成平台消息认证和身份映射，再转发，并负责回复。
- **公众号/企业微信**：需要各自的平台连接器，填写通用 App ID 占位值不能完成协议接入。

Webhook 出站发送 `{route_key, text}` 和 `Idempotency-Key`；桥接方必须转换平台格式、校验平台业务失败并去重。不要直接填入一个不兼容的群机器人地址。iLink 出站实现有独立的业务返回码检查和持久幂等，不代表其他桥接服务也有相同保障。

## 可靠性和隐私

iLink 的状态库包含连接凭据、游标、回复上下文与幂等状态，只挂载给微信服务，不写入 Git，也不包含在 Central 控制面备份中。消息处理失去响应时不会自动重放危险动作，先回面板核对结果。

主动发送依赖有效会话上下文。本地超过 24 小时未更新的上下文会拒绝发送，需要成员先发新消息；24 小时也不是平台保证的有效期。站内通知和可选 Server酱可作为独立提醒渠道。

模型只获得受限意图上下文；容器日志、SSH 密码和工具结果不自动进入模型上下文。即使如此，用户也不应主动在聊天里粘贴秘密或敏感研究材料。

## 部署验收

1. 未绑定消息不能操作资源；过期配对码明确失败。
2. 两个实际成员分别测试，只能操作授权资源；停用、解绑后拒绝访问。
3. 核对 GPU 与容器状态是否和面板一致，缺失监控不能当作空闲。
4. 使用可丢弃容器验证启动、停止/重启确认、日志及任务通知；不要试停真实训练。
5. 检查重复消息、网络超时与进程重启不会重复执行危险动作。
6. 主动通知需要实际检查渠道送达；“生成通知”或 HTTP 成功不能代替最终收件验证。

安装器默认只将基础 Web/API/Agent smoke 作为门禁，完整 Web/微信成员身份联调明确标为 `SKIPPED`。部署并配对测试成员后，运行 `sudo bash scripts/deploy/install_ubuntu.sh identity-smoke`；测试实例使用 `install_test_ubuntu.sh identity-smoke`。也可设置 `GSM_RUN_MEMBER_IDENTITY_SMOKE=1`，要求安装或测试 `start` 时通过完整联调。该检查需要临时交互凭据和已配对路由，不会将它们写入环境配置。未执行不能记为通过。面板隧道不会自动公开微信消息入口，也不应直接暴露整个 Agent。
