# GPU Server Manager 0.3.0 预发布：用户操作手册

适用版本：`0.3.0-rc.5`。面向普通成员、教师和管理员。实际功能由管理员部署的镜像、应用网关和外部服务决定；页面显示“尚未配置”时，应由管理员完成接入。

本文使用导航表和流程图说明操作，不使用含真实账号、服务器地址或口令的截图。示例地址均为占位值。服务器安装及维护见[部署与功能手册](deployment-guide.md)。

## 1. 第一次使用

从管理员取得面板 HTTPS 地址、网页用户名和初始密码：

1. 打开面板，输入账号和初始密码。
2. 按提示设置自己的新密码。首次密码设置未完成时，不能直接进入正常工作区。
3. 管理员按要求配置验证器 TOTP，并保存恢复码；普通成员不需要管理员的动态验证码。
4. 进入「我的账户」检查身份信息；需要微信或通知时，再自行绑定。

没有通用默认密码。网页密码、容器 SSH 密码、独立 SFTP 密码是不同凭据；不要把它们混用。遇到证书不受信任提示，请向管理员取得正确证书或访问地址，不要直接忽略告警。

### 从哪里开始

| 我想做什么 | 页面入口 |
| --- | --- |
| 看总体状态、故障提示 | 概览；管理员还能看到服务状态与诊断 |
| 看个人额度和资源曲线 | 资源概览 |
| 创建、启动、停止或连接容器 | 容器列表 |
| 上传文件、建目录、重命名 | 我的数据 |
| 申请更多 CPU/内存或 GPU | 额度申请；教师和管理员页面叫“审批” |
| 有 GPU 空闲时提醒我 | GPU 空闲提醒 |
| 修改密码、绑定微信、设置通知 | 我的账户 |
| 提交打印 | 打印 |
| 教师查看分配给自己的学生 | 学生、使用情况 |
| 管理员管理成员和全站设置 | 成员管理、系统、审计与告警 |

普通成员主要看到自己的容器和资源；教师有其授权教学范围；管理员有全站管理视图。**教师和管理员都不是自动不限额度的账号**，“超级用户”是管理员单独设置的额度豁免标记。

## 2. 理解个人额度

默认个人额度为 **8 核 CPU、8 GiB 内存、0 张 GPU**，管理员可以统一修改。页面会显示已使用、有效上限和剩余额度。

管理员自己创建和启动容器时也受个人额度检查。需要豁免时，进入「系统 → 超级用户」，搜索对应成员并勾选；仅拥有管理员角色不会自动启用该标记。

额度计算的是同时运行容器的**配置总额**，不是任务此刻的 CPU 百分比或显存实际使用量。例如：

| 容器 | 配置 | 当前状态 | 计入个人额度 |
| --- | --- | --- | --- |
| 项目 A | 4 核 / 4 GiB / 0 GPU | 运行中 | 是 |
| 项目 B | 4 核 / 4 GiB / 0 GPU | 运行中 | 是 |
| 项目 C | 8 核 / 8 GiB / 1 GPU | 已停止 | 否 |

在默认额度下，A+B 可以同时运行；再启动 C 会超额。即使 A 的实际 CPU 利用率只有 1%，它仍占用配置的 4 核额度。启动中、状态未知等尚未确认释放的资源也会暂时计入，避免重复分配。

停止的容器可以修改配置，但启动时会重新检查个人额度。单个容器无论是否超级用户，都不能配置超过服务器可分配的 CPU、内存或 GPU。GPU 还必须实际空闲，额度获批不代表某张卡已经替你保留。

## 3. 申请临时额度

进入「额度申请 → 申请临时额度」：

1. 填写使用期间所需的 **总 CPU、总内存、总 GPU 数**。例如现有 8 核，希望提高到 16 核，就填 16，不是填额外增加的 8。
2. 选择开始和结束时间。单次最长 366 天；选择未来开始时间时，即使提前通过，也要到开始时间才能使用。
3. 写清楚项目、用途和预计运行时间，再提交。
4. 在下方记录查看每一级的状态、审批人、时间与说明。

```mermaid
flowchart LR
    A[提交总额度和用途] --> B[一级管理员]
    B --> C[二级教师]
    C --> D[批准且到开始时间]
    D --> E[临时额度生效]
    E --> F[到期回退]
```

审批人由管理员为全站统一设置。未配置的阶段自动跳过；两级都未配置时自动批准。被拒绝后可根据说明调整需求，重新申请。多份同时有效的批准取各项较高上限，不会叠加成无限额度。

**到期不会自动停止正在运行的任务。** 额度回退后，如果当前占用已经超出上限，页面会提示，后续超额启动被阻止。请在到期前完成任务、主动停止不用的容器，或及时申请延长使用期间。停止后再次启动也按当时有效额度检查。

## 4. 创建容器与选择环境

进入「容器列表 → 创建容器」，按向导选择服务器、环境、资源、挂载和 SSH 初始密码。核对创建后是否立即启动；基础额度为 0 GPU 时，需先申请 GPU 额度，或先保存为停止状态。

### 该选哪个镜像

| 需求 | 建议选择 | 自己还需做什么 |
| --- | --- | --- |
| 用 pandas/sklearn 做分析、画图或 Notebook | Python 数据分析工作台 | 安装项目独有依赖 |
| 直接用 torch 做 GPU 训练 | PyTorch CUDA 工作台 | 申请 GPU 额度、选择空闲卡、安装项目额外依赖 |
| 自己选 torch/其他框架或编译 CUDA 扩展 | 纯净 CUDA 开发环境 | 自行安装框架；确认驱动和 CUDA 兼容 |
| 已有 requirements，需要干净 Python | Python 精简基础环境 | 建 venv 并安装依赖 |
| Go 项目 | Go 开发环境 | 下载依赖或提供 vendor |
| 通用 Linux / C/C++ | Ubuntu 基础环境 | 按项目安装工具 |

页面的分类、版本、预装包、GPU 支持和管理员推荐标记是选择依据。Python 工作台不一定带 PyTorch；“CUDA”也不代表已安装 torch。PyTorch 工作台的 CUDA runtime 不包含 `nvcc`，需要编译工具时选择相应开发镜像。

不同 Python 版本是不同镜像，不是在已经使用的环境中无损切换。先选择项目兼容的版本，再安装依赖。推荐版本变化不会自动升级已有容器。

### 创建后做一次最小验证

在网页终端或 SSH 里执行：

```bash
cd /workspace
python --version
python -m pip check
```

数据分析工作台可以检查：

```bash
python -c "import numpy, pandas, sklearn; print('科学计算依赖可用')"
```

PyTorch GPU 工作台可以检查：

```bash
python -c "import torch; print(torch.__version__); print('CUDA:', torch.cuda.is_available()); print(torch.cuda.device_count())"
```

没有分配 GPU 的容器中，CUDA 显示不可用可能是正常情况。真正训练前还应验证项目使用的算子和依赖，而不只看 `import` 成功。

## 5. 连接容器

### 网页终端

容器启动后，在连接区域点击「一键连接网页终端」。不需要重新输入容器密码，但依赖有效的网页登录会话。刷新网页或关闭终端后，交互任务可能断开；长任务应按项目需要使用 `tmux`、`screen` 或可靠的任务管理方式。

### SSH 密码

容器连接区域会向所有者显示已保存的 SSH 密码和连接命令，分别点击复制即可。命令示例：

```bash
ssh researcher@compute.example.edu -p 22001
```

输入该容器的 SSH 密码。地址和端口必须复制页面实际值；不要照抄本文端口，也不要将网页用户名填成容器登录用户。标准 SSH 命令不会把密码直接写在命令行中，这是正常行为。

Xshell、VS Code Remote SSH 等客户端使用同样的主机、端口和用户名。若页面提示旧密码未保存，可在连接/配置区域重新设置密码；已有旧密码本身不一定失效。

校园网 SSH 只在管理员允许的网络范围可达。外网能打开面板不代表也能直连 SSH；可先使用网页终端，再向管理员确认网络入口。

### SSH 短期证书

不希望每次输入密码时，可使用本地密钥与平台签发的短期证书：

```bash
ssh-keygen -t ed25519 -f ~/.ssh/gsm_member
```

1. 在 SSH 证书向导粘贴 `~/.ssh/gsm_member.pub` 的内容，**只提交公钥**。
2. 下载签发结果，保存为 `~/.ssh/gsm_member-cert.pub`，与私钥同目录。
3. 使用页面证书连接命令；客户端需要使用对应私钥。
4. 证书到期后重新签发；平台不保存你的本地私钥。

## 6. 我的数据：文件放在哪里

每个账号都有独立个人目录，同一账号的容器通常通过 `/workspace` 访问它。其他普通成员不能通过页面、SFTP 或可选挂载进入你的目录。同一账号的多个容器访问同一批文件时，请避免同时覆盖同一个输出文件。

```text
我的数据 /                         容器内
├── projects/                     /workspace/projects/
├── datasets/                     /workspace/datasets/
├── models/                       /workspace/models/
└── results/                      /workspace/results/
```

这只是建议组织方式，子目录可以自行命名。

### 网页管理

在「我的数据」中：

- 点击目录进入，使用路径导航返回上一级。
- 创建项目子目录；上传和下载文件。
- 点击重命名，为文件或目录输入新名称；目标已存在时不会静默覆盖。
- 上传单文件上限为 100 MiB，单账号最多同时进行 5 个网页上传任务；更大的文件使用 SFTP。

网页支持的操作以按钮为准；当前移动、批量处理和删除主要通过 SFTP 完成。不要用 `..`、绝对宿主路径或符号链接访问其他位置；这些路径会被拒绝。

“数据盘总容量”和“全盘可用”是整块盘的空间，不是你的个人磁盘配额。当前 CPU/内存/GPU 额度也不是文件存储额度。

### SFTP 大文件上传

如果管理员已启用独立 SFTP：

1. 在「我的数据 → SFTP 数据连接」设置独立密码，或登记 SSH 公钥。
2. 复制页面显示的 SFTP 主机、端口与生成的用户名。
3. 在 Xftp、WinSCP 或 FileZilla 选择 **SFTP** 协议，填写这些信息。
4. 上传到自己的根目录或子目录。容器中相同文件出现在 `/workspace` 对应位置。

独立 SFTP 不需要启动容器，使用的用户名也不是容器的 `researcher`。首次连接应按管理员提供的信息核对主机指纹。SFTP 可以覆盖、移动和删除文件；删除个人目录中的文件会影响访问它的所有本人容器。

待离组账号的 SFTP 只允许查看和下载；停用或归档后不可访问。权限由后台周期同步，变化时旧连接会断开；账号恢复有效后重新连接即可按新权限使用。

### 避免占满 NVMe

容器系统、包安装和 `/workspace` 以外的可写层通常在 NVMe；个人数据在数据盘。把训练数据、权重、输出及大缓存放在 `/workspace`，例如按项目约定设置模型缓存目录。

停止容器不释放已安装环境。删除容器会丢失其可写层；**先确认需要保留的文件已经在 `/workspace` 或独立备份中**。环境导出 JSON 和容器配置快照都不能代替个人文件备份。

## 7. 打开 JupyterLab 与 TensorBoard

启动容器，在详情的「应用与 Python 环境」操作：

1. 选择实际运行项目的 Python 环境；默认解释器不一定是你自己创建的 venv。
2. 点击「打开 JupyterLab」。首次缺少应用依赖时会准备独立环境，观察进度提示。
3. 新页面打开后，项目文件位于 `/workspace`。
4. TensorBoard 读取 `/workspace/runs`，训练脚本应将 event 文件写入该目录；镜像需已安装 TensorBoard。

准备 Jupyter 主要安装应用本身，不会替你安装所有项目依赖，也不会升级项目里的 torch。无外网时需要管理员提供离线包；准备失败时保留错误信息，不要连续重复点击。

高级选项可填写虚拟环境 Python 的绝对路径并重新准备应用。切换环境前先保存 Notebook 并停止旧应用。可以在 Notebook 中运行：

```python
import sys
print(sys.executable)
```

以确认正在使用的解释器。

打开应用的票据只有短时有效，不要把地址收藏为长期入口或转发给别人；每次从面板重新打开。停止容器会停止应用，重新启动后需要再次打开。网页登录失效时，先返回面板登录。

如果浏览器拦截新标签页，使用面板显示的“继续打开应用”链接。若提示应用入口未配置，需管理员配置独立 HTTPS 应用来源；用户无需自行公开 Jupyter 端口。

## 8. 管理容器与复用环境

### 停止与修改配置

在容器列表查看状态，进入配置页面前先停止需要调整的容器。CPU/内存变更与 GPU/SSH 绑定变更的处理不同；后者可能需要为停止容器生成快照并重建，所以耗时较长。

保存后确认配置已更新，再主动启动。数据盘挂载目录保持独立存放。若操作超时或显示“结果未知”，先刷新并查看状态或恢复提示，避免重复提交删除等操作；需要管理员对账时请提供容器 ID 和发生时间。

### 导出与复用

「导出环境」生成 JSON，记录镜像、资源、挂载配置以及可读取到的 Python/conda 等版本信息。停止容器只能导出已保存配置；读取当前安装依赖需要容器运行。

「复用配置」或新建向导的“导入环境配置”会帮你填入新容器配置，随后仍需重新确认资源、GPU 和密码。

它们**不复制工作文件、容器可写层、密码、SSH 证书或完整环境**。依赖版本清单是复现参考，仍需实际安装。编辑“启动命令说明”只是记录操作提示，不会在开机时自动执行，勿在里面填写密钥。

## 9. GPU 空闲提醒与通知

在「GPU 空闲提醒」选择目标服务器、卡数、每张至少显存和预计时长：

1. “查看当前空闲”获取当前匹配结果。
2. “订阅空闲提醒”等待资源符合条件。
3. 默认有效期 24 小时；可以取消，也可以续订并再次提醒。

**提醒不预留资源，先成功启动的人先用。** 收到通知后仍需有有效 GPU 额度；别人先启动、采样变旧或配额到期都可能导致你的启动失败。预计时长用于需求说明，不会到了时间自动结束你的任务。

### 配置接收渠道

在「我的账户 → 通知与微信提醒」中，按页面链接到 Server酱取得自己的 SendKey，保存、启用并发送一次测试通知。密钥留空保存表示保留已有值，解除绑定会移除配置。

站内始终保留通知记录。外部发送受网络、平台套餐和本地每日上限影响，站内“已处理”不等于已经人工阅读。不要把 SendKey 发给其他成员。

### 微信机器人

管理员部署微信连接器后，在账户页生成配对码，到机器人会话发送：

```text
/pair <本次生成的配对码>
```

配对码短时有效、单次使用。绑定后可以询问功能、服务器和本人资源情况，或发起平台支持的操作；涉及变更时按机器人要求确认。模型问答不代表已经执行了命令，真正操作结果以面板和审计为准。

微信不能代替网页登录密码，也不会因此给你其他成员的权限。长期没有互动时，个人微信通道可能需要你先主动发一条消息才能继续推送；需要稳定提醒时同时保留站内与其他已部署渠道。

## 10. 打印文件

进入「打印」，选择在线打印机，上传支持的 PDF/图片，检查页面、份数和选项，再按页面要求精确确认。默认上传大小上限为 100 MiB，实际限制可能由管理员调整。

确认前仔细检查文件和份数；确认后任务可能已经进入 Windows 打印队列。`completed` 表示队列报告完成，不保证纸张已经取走。`delivery_unknown` 表示可能已送入打印机，先与管理员核实，避免重复打印。

没有打印机或持续离线时，需要管理员检查打印电脑开机状态、Agent 心跳、驱动与打印机本身。打印流程不会替你释放或停止 GPU 容器。

## 11. 教师的常用操作

教师账号没有学生毕业时间，不需要人为填写学籍到期日期。其计算操作仍按有效个人配额执行；管理员需要时可单独设置超级用户。

- 「学生」查看管理员分配给自己的学生；成员导师归属由管理员维护。
- 「使用情况」查看授权范围内的资源使用。
- 「审批」查看自己当前负责的临时额度申请，核对用途、总额度和时间，填写审批说明后通过或拒绝。

只有当前级别指定的审批人才能处理该级。教师角色本身不意味着可以处理所有申请。一级通过后二级才进入待处理；有权审批自己申请的情况遵循全站当前规则。

## 12. 管理员操作

### 成员管理

邀请成员时选择角色、成员类型，学生填写学籍信息；教师选择教职工类型。将初始密码通过合适方式交给对应成员，首次登录会要求其改密。微信配对由成员在自己账户里完成。

新建学生时可以直接选择刚创建、尚未首次登录的教师，列表会标注「待首次登录」；也可以在学生详情中分配或更换导师。导师完成首次登录改密后才能查看学生。已停用、离组或归档的账号不可分配；个人导师归属和系统设置中的统一额度审批人分别维护。

支持 CSV 导入预览；优先下载页面模板，不自行猜测列名。批量提交前检查用户名、角色、学籍与导师。任意一行校验失败时不会写入半批成员。

停用账号会撤销访问能力，但不会自动停止其正在运行的容器。挂载成员私有目录的容器不能直接转交给另一人，否则可能暴露原成员的全部文件。交接时由接收人创建自己的容器，再经原所有者授权显式复制所需项目文件；归档前由管理员核实容器与数据的处理结果。

### 系统设置入口

「系统」按类别展示入口，点击后在弹窗配置，关闭后返回总览：

| 入口 | 管什么 | 需要注意 |
| --- | --- | --- |
| 配额与审批 | 基础额度、一级管理员、二级教师 | 两级为空时申请自动通过；修改会影响待处理环节 |
| 超级用户 | 搜索成员、分页、勾选额度豁免 | 管理员也需单独勾选；不改变角色，不能突破物理限制 |
| 镜像与环境 | 分类、搜索、版本、推荐与暂停新建 | 调整策略不改变已有容器，不自动构建镜像 |
| 微信 Agent | 主备模型配置与服务状态 | 密钥只供服务使用；按提示完成管理员验证 |
| 打印机接入 | 打印电脑、部署包、凭据和心跳 | 注册后还需在 Windows 电脑实际安装 |
| 控制面备份 | 创建、校验、查看及发起恢复 | 控制备份不含用户训练文件；恢复需要主机维护步骤 |
| 版本与更新 | 查看发布版本、准备、安装和回退 | 仅管理员可操作；每次操作需要动态验证码，恢复失败时需主机维护人员处理 |

镜像与超级用户列表支持搜索和分页；先缩小范围再操作。涉及凭据签发的弹窗可能只显示本次明文值，关闭前按需要安全保存。

### 安装新版本

进入「系统 → 版本与更新」后，先确认主机升级服务显示“已连接”。未配置真实发布仓库会显示待配置；稳定版通道不推送候选版本。发布检查缓存 5 分钟，升级任务每 5 秒刷新。点击“查看发布说明与下载”只打开发布说明。

1. 阅读发布说明，安排控制面维护时间，再点击“准备新版本”，输入当前管理员的 6 位动态验证码。
2. 等待“准备完成”，核对版本和有效期。准备记录有效 1 小时；此时还没有安装。
3. 等验证器显示**下一组验证码**，点击“升级到…”；输入页面要求的 `UPGRADE <版本>` 短语和新的验证码。每组验证码只能用于一次升级操作，不需要再输入管理员密码。
4. 查看“构建新版本”“保存升级前恢复点”“迁移控制数据库”等进度。只有安装任务显示“操作成功”，并且当前版本已变化，才算完成。

维护期间面板登录、管理操作以及依赖管理接口的微信和打印功能会暂时不可用。升级器不会停止用户研究容器或移动个人文件；已有 SSH 训练任务与管理页面是否可用是两回事。提前保存页面上的未提交内容，容器内的研究数据仍需自行备份。

若连接中断，页面会重新查询进度，不会自动重发安装。先核对操作 ID 和任务结果；仅在确认没有任务执行时，才使用“已核对任务状态，解除等待”。“已恢复升级前版本”表示本次没有保留新版本；“需要人工恢复”时联系主机维护人员，不要继续提交升级。

“回退到升级前”会恢复升级前的管理配置与数据库，升级后新增或修改的成员、额度、管理记录会被覆盖。操作需要勾选确认、输入页面给出的 `ROLLBACK <恢复点ID>` 和新的动态验证码。个人文件与正在运行的研究容器不会随管理记录一起倒退，回退后请管理员核对容器与记录是否一致。

主机服务未连接、仓库未公开或找不到可安装资产时，由维护人员检查部署；普通成员不需要自行配置更新。

### 概览和存储告警

「概览 → 服务状态」汇总采集、Agent、存储等健康情况，相关事件可进一步诊断。图表中的实际利用率和配额中的已分配额度含义不同，不应直接比较百分比。

GPU Xid 项提示“采集不可用”或 `collector_unavailable` 时，表示系统暂时读不到宿主内核日志，应由管理员检查日志挂载和权限；不能据此判断没有 GPU 错误，也不能直接认定硬件损坏。日志可读且最近 10 分钟未发现 Xid，仅说明这一时间窗口没有匹配记录。

部署管理员启用容量保护后，运行时盘达到 80% 使用率或低于 100 GiB 可用空间会预警；达到 90% 或低于 50 GiB 时限制新增容器、镜像下载和快照生成，inode 不足也会触发保护。

保护不会停止现有任务，也不是每容器磁盘额度。遇到告警需定位镜像、可写层、缓存、日志或数据位置，不能直接无差别删除别人的容器或镜像。

### 恢复资料的区别

| 资料 | 保存什么 | 保留规则 |
| --- | --- | --- |
| 控制面备份 | 成员、权限、配置、控制记录及允许打包的密钥 | 最新 10 份；活动恢复引用受保护 |
| 升级恢复点 | 本次升级前的配置、控制数据库与 Agent 状态，以及旧镜像引用 | 主机维护人员管理，独立于网页的 10 份备份；不自动过期清理 |
| 容器配置快照 | 重建配置前的容器环境等镜像内容 | 每容器最近 3 份，超过 30 天清理，至少最新 1 份；使用/恢复中受保护 |
| 个人文件备份 | 数据集、代码、模型、结果 | 需管理员另行建立，不包含在上述控制备份内 |

保护中的快照可能让数量超过 3，不一定是清理失败。快照归档落到数据盘，并不意味着 Docker 当前使用的镜像层已从 NVMe 删除。网页中的控制面恢复不是一键恢复所有个人数据。

## 13. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 提示超过个人额度 | 看“已用 + 本次需求”与有效上限；停止不用的容器或申请总额度提升 |
| 已获 GPU 额度但不能启动 | 额度开始时间、有效期、GPU 是否被占用、单容器容量与服务状态 |
| 容器 CPU 利用率低但额度已满 | 额度按配置总额计算，低负载不会自动归还额度 |
| SSH 连接超时 | 容器是否启动、是否在允许校园网、主机/端口是否复制正确 |
| SSH 密码错误 | 是否误用了网页/SFTP 密码；检查该容器的独立密码 |
| Jupyter 开得慢 | 看首次准备进度；离线包/网络是否就绪，避免重复开启准备任务 |
| Notebook 找不到自己安装的包 | 核对所选 Python 和 Notebook 内 `sys.executable` |
| 数据上传完成，容器找不到 | 核对是否本人容器，并在 `/workspace` 而非当前 home 目录查找 |
| SFTP 登录失败 | 使用页面生成的 SFTP 用户名、独立密码和独立端口；不是容器 SSH 参数 |
| 准备成功后升级提示验证码已使用 | 等待验证器显示下一组 6 位验证码；准备和安装各验证一次 |
| 升级时页面断开或登录暂不可用 | 等待页面重连并核对任务状态，避免重复提交；需要人工恢复时联系维护人员 |
| 停止容器后 NVMe 没下降 | 停止只释放计算占用，镜像和可写层仍保留 |
| 数据盘有空闲仍提示存储不足 | 运行时 NVMe 与数据盘不同，确认触发保护的实际设备 |
| GPU 监控无数据 | 查看采集状态、数据时间和服务告警，不把未知当作空闲 |
| 删除/改配置后显示结果未知 | 刷新后保留容器 ID 与时间，交管理员对账，不连续重试危险操作 |
| 微信未收到提醒 | 先看站内记录，再检查绑定、每日额度、网络和渠道会话上下文 |

报障时提供版本、时间、所在页面、容器 ID、错误文字及已经尝试的步骤。截图前隐藏密码、密钥、恢复码和私人文件内容。
